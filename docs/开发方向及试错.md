## 二、BUG 上报系统 ✅ 已实现

### 方案：飞书群自定义机器人 Webhook

**为什么选它**：
- 完全免费，无付费墙
- `GM_xmlhttpRequest` 穿透 CORS，无需 Cloudflare Workers 中继
- `@connect open.feishu.cn` 抑制 Tampermonkey 安全弹窗
- Webhook URL 可随时在群内移除/重新生成，风险可控

### 实现细节

- `showBugReportDialog()` — 两步弹窗
  - Step 1：「脚本运行时是否出现了异常？」是/否
  - Step 2：说明（告知可能弹出油猴安全对话框）+ 可选文本输入 + 确认上报
  - 发送中 → ✅成功 / ❌失败（可重试，保留已输入文字）
- `collectDiagnosticsJSON()` — 4 层 30+ 诊断字段
- `sendBugReport(userMessage, callback)` — `GM_xmlhttpRequest` POST
- 全局 `error` + `unhandledrejection` 监听器 → `window._yktLastError`

## 三、非视频页面跳过 — 试错记录

### 问题描述

视频间不连续（video/41157053 → homework/41157054），脚本构造 `/video/41157054` → 杂交页面：Vue 视频组件复用，显示旧视频 → 播放 30 分钟 → `waitForCompleted()` 超时才跳过。

### 试错过程

| # | 尝试 | 结果 | 失败原因 |
|---|------|------|---------|
| 1 | `getVideoStatus()` 返回 `(unknown)` 时跳过 | ❌ | 修复 regex 后杂交页面返回「完成度：0%」→ 绕过检测 |
| 2 | 播放前检测 `xt-bigbutton` 可见性 | ❌ | 真实视频播放前 bigBtn 也可见 |
| 3 | 检测页面「完成度不再更新」文字 | ❌ | 该文字是已结束课程的全局提示，非杂交独有 |
| 4 | 播放后检测 bigBtn（8 秒宽限） | ❌ | 依赖 SPA 跳转后状态，SPA 本身是根因 |
| 5 | **`location.href` 替代 `$router.push`** | ✅ | 全量页面重载 → Vue 完全重建 → 无状态泄漏 |

### 最终方案

`clickNextUnit()` 中：
1. 读 `vm.nextLeaf.id`
2. `sessionStorage._ykt_auto_continue = 1`
3. `location.href = ...`（完整页面重载）

脚本启动时检测 sessionStorage 标记 → 自动恢复 `startSession()`。

**附带好处**：
- `findVideo()` 3 秒快速失败（无 `<video>` 元素时不等 30 秒）
- 真实视频 `waitForCompleted` 超时 → `location.reload()` 重播（不做跳过）
- bigBtn 播放后 8 秒检测保留为 safety net

### 关键技术教训

1. **检测时机 > 检测信号**：先播放再检测，而非播放前猜测
2. **修复一个 bug 可能暴露另一个**：regex 改进让杂交页面绕过检测
3. **SPA 跳转不适合该场景**：Vue 组件复用导致状态泄漏，`location.href` 全量重载虽然没有 SPA 快，但对可靠性提升巨大
4. **页面文字不可靠**：任何页面文案都可能因课程状态/版本变化，不能用作判别信号
5. **`xt-bigbutton` 是唯一可靠的跨页面判别信号**：真实视频播放后立即隐藏，杂交页面永远可见

## 五、关键技术约束（更新后）

1. **`@grant GM_xmlhttpRequest`** — 沙盒已验证兼容，不可退回 `@grant none`
2. **不上传任何用户隐私** — Cookie/姓名/学号/DOM 全文一律不碰
3. **用户操作 ≤ 2 步** — BUG 上报：点击按钮 → 点击确认（输入可选）
4. **零外部登录** — 飞书群机器人无需登录
5. **脚本内不放长期密钥** — Webhook URL 可随时撤销/重新生成，风险可控
6. **`location.href` 跳转** — SPA 跳转不适合跨类型页面导航，全量加载确保状态干净

## 七、长江雨课堂适配（v1.4）

### 用户反馈的 4 个问题与根因

| # | 用户反馈 | 诊断证据 | 根因 | 处理 |
|---|---------|---------|------|------|
| 1 | 播放中段出现断区（部分未被计入） | `video.src: ...-10.mp4`（分段视频） | 推测：倍速播放 + 播放器固定间隔上报 = 上报空洞；脚本无法直接控制播放器上报 | 无法根治；配合 #4 的「重播从头」可自愈；建议用户在断区严重时降速 |
| 2 | 播完一个视频后日志显示「全部完成」 | `.btn-next: 不存在`、`Vue实例: 未找到` | **确定**：长江无 `.btn-next`/`__vue__`，`clickNextUnit()` 返回 false → 误报 | ✅ `leafId+1` fallback 跳转 + 连续无视频保护（3 次停止） |
| 3 | 跳转后视频黑屏 | 分段 mp4、`video` 元素可能被播放器重建 | 推测：切段重建 `<video>` 元素，脚本全局 video 引用失效 | ✅ `watchPlaybackHealth()` 检测新元素并重绑（muted+play） |
| 4 | 断区后重播从 P 开始而非 A，断区永远无法覆盖 | `ykt_status.progress: 89` | 推测：播放器自动续播到服务端进度 | ✅ `guardAgainstResumeJump()` 重播场景检测跳跃 → 重置到开头（限 2 次） |

### 关键差异（华工 vs 长江）

| 维度 | 华工 scut | 长江 changjiang |
|------|-----------|-----------------|
| 视频页路径 | `/pro/lms/{sig}/{cid}/video/{leafId}` | `/v2/web/xcloud/video-student/{cid}/{leafId}` |
| 下一视频跳转 | `.btn-next` + Vue `nextLeaf.id` | 无按钮无 Vue → `leafId+1`（实测有效） |
| 「已完成」标记 | 播完出现 | 服务端持久状态（播完一次永久显示），可复用 |
| 视频源 | 单文件（推测） | 分段 mp4（`...-10.mp4`） |
| 续播行为 | 未知（假设无） | 有（reload 后 seek 到服务端进度） |

### 防死循环护栏（v1.4 新增）

- **连续无视频保护**：`_ykt_fallback_last/_count`（sessionStorage），连续 3 次 fallback 无视频 → 停止并提示
- **卡死刷新限次**：`_ykt_health_reloads`，长江卡死刷新最多 3 次 → 停止提示
- **防续播重置限次**：异常跳跃重置最多 2 次 → 放弃干预（防误伤分段切集）

### 待验证项（需要长江用户实测）

1. `leafId+1` 在作业/讨论夹在中间时是否跳对（连续无视频保护会兜底停止）
2. 黑屏是否确为元素重建导致（看面板日志「↻ 检测到新的 video 元素」）
3. 防续播是否生效（重播时应看到「↺ 播放位置异常跳跃」日志，且从 0 开始）
4. 断区是否因倍速上报空洞（若是，需要降速方案或播放器上报机制研究）

## 八、诊断采集升级（v1.5）

### 目标：正交高效 debug

长江只有一位测试用户。升级后形成「**用户明面描述现象 + 暗面自动采集**」两条正交信息流，用户只需：

1. 复现问题
2. 点面板「BUG上报」→ 输入现象描述（何时/何操作/期望）→ 确认
3. 完成——**无需在控制台执行任何命令**

### 暗面采集内容（自动）

- **媒体事件史**（20 条）：play/pause/seeked/stalled/waiting/canplay 等，带时间戳和 currentTime → 可直接还原「黑屏时发生了什么」「断区在哪一秒」
- **页面结构**：自定义元素列表（识别播放器组件）、播放器全局对象、关键选择器摘要（next/prev/finish 按钮文本 + 目录容器数量）
- **错误史**（3 条环形）：全局 error/unhandledrejection + video error 事件
- **脚本状态**：面板日志 50 条、sessionStorage 标记（fallback/health 计数）、引擎 flags
- **环境**：屏幕尺寸/DPR（判断播放器被隐藏等）

### 隐私边界

- 导航/状态按钮采文本（短文本）；**目录容器、播放器容器、头部栏只采数量不采文本**（防课程名/视频标题泄露）
- 不采集：Cookie、完整 DOM、localStorage 全文、姓名/学号

## 九、v2.0：2026 改版后的重写（本次）

### 触发

雨课堂把课程播放页整体换代了。用户给的新地址：

```
课程未完成页：https://scut.yuketang.cn/pro/lms/scut-89QA0744001577N/26776303/unfinished
视频播放页：  https://scut.yuketang.cn/ai-workspace/lms-graph/26776303/video/49200284?node_id=6526176&fromProIframe=1&isyth=1&is_chapter=1
```

和 v1.5 认定的 `/pro/lms/{sign}/{cid}/video/{leafId}` 完全不是一条路由。

### 侦察过程与发现（因为没有可用文档，全靠浏览器实测）

| 步骤 | 方法 | 结论 |
|---|---|---|
| 1 | `performance.getEntriesByType('resource')` 抓页面所有 XHR | 找出 20+ 个接口，锁定 `todo_list` / `sku_list` / `outline_entry` / `study_stat` |
| 2 | 直接 `fetch` 这些接口 | 返回 `{"msg":"XTBZ IS REQUIRED","error_code":40000}`（和 v1.x 记的坑一模一样） |
| 3 | `get_network_request` 读真实请求头 | 必需头：`xtbz` / `university-id` / `platform-id` / `x-client` / `terminal-type` / `x-csrftoken` |
| 4 | `document.cookie` 对照 | **全部可读**（`xtbz=cloud; university_id=2627; platform_id=3; csrftoken=…`），无需任何注入 |
| 5 | 保存 `todo_list` 响应体到文件再分析 | 拿到课程顺序 + `type`（0视频/4讨论/5作业）+ 完成后**立即从清单消失**的特性 |
| 6 | 监听 `POST /video-log/heartbeat/` | 找到进度上报机制，`et:"videoend"` 是完成态落地的触发点 |
| 7 | 保留 `xt-*` 自定义元素探测 | 播放器**没换**，`xt-bigbutton` / `xt-speedvalue` / `xt-playbutton` 全在 |

### 什么被推翻了

| v1.x 依赖 | v2 状态 | 原因 |
|---|---|---|
| `.btn-next` + `el.__vue__` → `vm.nextLeaf.id` | ❌ **整体废弃** | 新版生产构建 Vue 3 不暴露 `__vue__` / `__vueParentComponent` / `__vnode`，全部 `undefined`；页面也没有 `.btn-next` |
| 成绩单页 `li` 爬视频列表 | ❌ **整体废弃** | 新版不再需要：`todo_list` 接口直接给课程顺序的未完成清单 |
| `span.text` 读「已完成/完成度：N%」 | ⚠️ 降级为兜底 | 新版改到 `.rate-detail .el-tooltip.text` |
| 长江 `leafId + 1` fallback | ❌ **整体废弃** | 换成接口驱动后不再需要猜 leafId |
| 杂交页面 `bigBtn` 8 秒检测 | ❌ 删除 | 该策略本来是给「SPA 跳错页面」兜底的；v2 用整页跳转 + 只跳视频 leaf，前提不成立 |
| 「防续播守护」（检测播放位置异常跳跃） | ❌ 删除 | 新版实测 `location.href` 重载后视频从 0 开始，没有续播问题；留着反而是误伤风险 |
| `lib/core.js` 镜像模块 | ❌ **删除** | 覆盖率虚高（97%）且测的不是出货代码，改一边忘一边 |

### 什么被保留了

| 保留项 | 理由 |
|---|---|
| 模块 0 always-on-focus | 与页面版本无关，纯 `document` 属性伪造 |
| 模块 1 原型链拦截（`playbackRate` / `volume` / `pause`） | **播放器没换**，`xt-*` 还是那一套，拦截依然有效 |
| `location.href` 整页跳转 + localStorage 恢复会话 | v1.1 的结论在新版上依然成立且更稳 |
| 面板 UI + 飞书 BUG 上报 | 与页面版本无关 |
| 诊断采集（媒体事件史 / 错误史 / 日志） | 与页面版本无关，字段按新版重写 |

### v2 新增的坑（已解）

#### 坑 1：光装原型链钩子不会变 2 倍速

播放器在页面初始化时就设过一次 `playbackRate = 1` / `volume = 0.8`，
**那是在我们的钩子装上之前**。所以钩子只保证「以后有人赋值时改写成目标值」，
必须再**显式赋值一次**才会真的生效。

实测：注入钩子后 `video.playbackRate` 仍是 `1`，`video.volume` 是 `0`
（volume 是 0 因为播放器本来就在调它，说明它在持续赋值；playbackRate 只设一次）。

修复：`engagePlayback()` 显式赋值 + 800ms/2500ms 补两次 + 1 秒守护持续纠偏。

#### 坑 2：倍速会不会被判作弊

担心「2 倍速 + 固定间隔上报 = 上报空洞」，所以专门盯了心跳：

```
[heartbeat] cp=51.3 d=101.3 (每 ~5 秒一条，cp 每次 +10.1 → 确认 2x 生效)
[videoend]  cp=101.3 d=101.3
```

然后读回 `get_video_watch_progress`：`{completed: 1, watch_length: 102.3, video_length: 101, rate: 1}`。

**结论：不会被判**。服务端统计的是视频时间轴的播放量（`watch_length` 甚至略大于
`video_length`），不是墙钟时间。`rate` 字段固定回 1，说明它读的是播放器内部状态而不是真实倍速。

#### 坑 3：`todo_list` 需要在场才能判断「当前是否真完成」

只看页面「已完成」文案有过竞态（v1.2 就踩过）。
v2 用了更硬的信号：播完后**再查一次 `todo_list`，看当前 leaf 还在不在清单里**。

- 还在 → 服务端没确认 → 重播（最多 2 次）
- 不在 → 确认完成 → 跳下一个

这个判据同时天然解决了讨论/作业跳过的需求（`filter(type === 0)`）。

### v2 的防御性设计

| 场景 | 护栏 |
|---|---|
| 服务端迟迟不确认完成 | 同 leaf 最多重播 2 次 → 之后跳过 |
| 连续找不到 `<video>` | 连续 3 次停止并提示 |
| 播放卡死 | 停滞 45s 才刷新，同会话最多 3 次 |
| 播放异常结束 | 同 leaf 最多重试 2 次 |
| 接口全挂 | 退回点站内「下一节」箭头，再不行停机报错 |
| 主循环 | `while (guard++ < 500)` 硬上限 |

### 测试策略的改变（重要）

v1.x：纯函数抄一份到 `lib/core.js` → 对它写测试 → 覆盖率 97% 很好看，但**测的不是出货代码**。

v2.0：脚本自己 `window._ykt.pure = {...}` 导出纯函数，测试 `import` 出货脚本本体。

```js
// tests/core.test.js
beforeEach(async () => {
  vi.resetModules();
  await import('../yuketang-auto.user.js');   // 真·出货代码
  pure = window._ykt.pure;
});
```

- 覆盖率从「97%（镜像）」变成「28% 语句 / 33% 行（出货脚本本体）」
- **数字变难看了，但那是真的**：剩下 70% 是 DOM 交互 / 接口调用 / 面板 UI，
  jsdom 本来就跑不到，只能在真实浏览器里验证
- 好处：再也不会出现「改了脚本忘了改镜像」

### 本地无油猴的调试手法

MCP 的 Chrome profile 里没装油猴，但可以这样在真实页面上跑出货脚本：

```js
const r = await fetch('http://127.0.0.1:8124/yuketang-auto.user.js?t=' + Date.now());
(0, eval)(await r.text());
localStorage.setItem('_ykt_engine_active', '1');
window._ykt.start();
```

要点：
- 本地静态服务器必须带 `Access-Control-Allow-Origin: *`，否则 https 页面跨域 fetch 失败
- `127.0.0.1` 属于 potentially-trustworthy origin，Chrome 不会按混合内容拦截
- `location.href` 整页跳转后脚本会丢，**每跳一页要重新注入**（会话状态在 localStorage 里会自己续上）
